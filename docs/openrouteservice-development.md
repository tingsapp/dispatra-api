# Development truck routing with openrouteservice

Set server-only `ORS_API_KEY` and `DISPATCH_ROUTING_PROVIDER=openrouteservice` in the local API environment. Restart the API and operational worker after changing configuration. Keep the existing `ROUTING_PROVIDER` for standalone commercial pricing and unassigned map previews. The November 3 live acceptance release uses this same opt-in provider at the owner’s request. Its six-location planning limit, quota limits and lack of live traffic still apply; use `tomtom` when the production account and truck fleet are ready. On the live server, keep the key in `/etc/dispatra/api.env` and set `ORS_ROUTE_CACHE_DIR` to private storage writable by the API and workers.

The adapter calls HeiGIT’s `driving-hgv` Directions endpoint with saved exterior dimensions, gross weight and optional axle weight. Weight is converted from kilograms to tonnes. Dangerous goods remain blocked pending classified routing support. Missing truck facts and provider failure never fall back to regular car routing.

The Matrix endpoint does not support the additional vehicle restriction options. Therefore development planning builds directed pair travel times from restricted Directions calls, with a maximum of six locations including the driver origin (up to 30 calls per plan). Repeated pairs and geometry share a one-hour server cache across requests, scoped by tenant and exact request/vehicle constraints. Concurrent identical requests share one provider calculation. A private persistent cache in `api/.local/route-cache` is shared by local API/workers and survives their restarts (512 entries, 32MB total), with a per-process hot layer (256 entries, 16MB). `ORS_ROUTE_CACHE_DIR` can select a persistent volume in deployment. Files are private, checksummed and atomically replaced; cross-process locks coalesce identical misses. Expiry remains one hour from the original calculation and is not extended by restart/read. Expiry, eviction or deleting the storage causes a fresh calculation. Failed/incomplete responses are not retained. Assignment permissions and current fleet/order constraints are checked on every action, not cached. Quotas can still be reached by repeated plans or multiple users; quota errors are explicit and do not trigger automatic retries or a paid fallback. Split larger plans or use the production provider.

Assigned order geometry identifies OPENROUTESERVICE and includes attribution to openrouteservice/OpenStreetMap contributors. Planning records ORS_TRUCK_NO_LIVE_TRAFFIC. The adapter does not supply live traffic; the existing traffic estimator returns no live provider estimate while this provider is selected. This limitation must not be presented as zero traffic delay. Customer pricing, tenant checks, capacity, timing, custody and assignment version checks remain in their existing shared use cases.

Verification: live public-coordinate HGV geometry and a two-location restricted matrix succeeded with the configured key. Unit transport/planning tests cover restrictions, kilogram conversion, missing facts, hazardous cargo rejection, caching, provider selection, route completeness and summary-only responses. Full database assignment tests were not run as part of this switch.

Monitor route-shape queries and recommendation panels no longer automatically refetch on browser focus/reconnection; explicit checks and changed order keys still fetch. Google basemap loads and unassigned Google road previews remain separate; this cache does not retain Google content or live traffic.
