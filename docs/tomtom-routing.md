# TomTom operational truck routing

Google Maps remains the dispatcher Monitor basemap. TomTom REST APIs supply operational truck travel times, traffic estimates and assigned-Order road geometry. The driver app continues to supply on-duty GPS; no ELD integration or new navigation app is included.

## Setup

1. Create a TomTom key with **Routing API** and **Matrix Routing v2 API** enabled. A separate Traffic API selection is unnecessary for traffic-aware route times; enable it only for a future standalone traffic feed.
2. Store `TOMTOM_API_KEY` only in the server environment (`api/.env` locally, protected deployment secrets on the server). Never use a `VITE_` variable, commit it, or send it to a client. Rotate a key shared in chat before production.
3. In Settings → Vehicle Types, save verified outside length/width/height and a conservative maximum loaded gross weight, including trailer/load, for each specific configuration. Outside length, width, height and loaded gross weight are mandatory when creating or saving a Vehicle Type; maximum axle weight alone is optional. Existing incomplete types remain readable without fabricated values, but must be completed before their next save. Every registered vehicle of that type uses these shared values automatically; there are no routing fields in the vehicle form. Different physical sizes, bodies or trailers require separate types. Cargo-space dimensions and payload capacity remain independent. Existing per-vehicle measurements remain stored and act as a compatibility fallback only while the type has never been configured. Saving a type profile supersedes those old values; new saves cannot clear a configured type profile. Historic explicit nulls remain readable without reviving old vehicle facts. Older API clients omitting the field preserve its stored presence/value. Switching a vehicle’s type without sending legacy measurements clears its old per-vehicle routing facts. Existing routing measurements cannot change while any vehicle of the type has a planned/in-progress Route. Before TomTom is enabled, first-time setup of a missing type profile is permitted when all linked active-route vehicles also lack legacy measurements. This only adds the missing facts: existing Routes, assignments, stops, cargo custody and prices remain unchanged. Later profile changes remain locked. Gross weight must cover the type and its registered vehicles’ payload capacities.
4. After verifying fleet profiles and the account’s production permissions, set `DISPATCH_ROUTING_PROVIDER=tomtom` and restart the API and operational workers with that environment. Leave the override blank to retain the existing provider. Provider selection is global to that deployment: do not enable it until every vehicle used for dispatch has a selected type with a valid profile (or preserved legacy measurements). Keep `ROUTING_PROVIDER=google` and the existing Google keys where Google geocoding, commercial standalone distance pricing or static tracking maps are required.

Operational assignment/live insertion use truck matrices with traffic. They do not change customer prices. Missing dimensions, unclassified dangerous goods, missing keys and provider failures require dispatcher review; they never silently use a car route. Hazardous goods classification/avoidance is not implemented. Loaded weight must cover the actual truck and load; a saved profile does not certify legal access or replace posted restrictions.

Matrices have at most 50 locations including the driver origin and use synchronous chunks of at most 100 cells. Each matrix cell can count toward usage, including diagonal cells. Candidate screening remains the existing local estimator; the final assignment rechecks road travel. Matrix travel times use the requested departure for each pair; they are planning estimates and do not simulate progressive service/departure times for every possible permutation. No persistent TomTom matrix/geometry cache is added.

## ETA and map behavior

The existing Order Watch worker obtains current route legs outside the business transaction. It revalidates route version, assignment generation, on-duty session and GPS before storing the estimate. Known booked service durations are included before subsequent visits; unknown handling time stops downstream prediction. Monitor and the read-only dispatch assistant expose only current matching evidence (GPS no older than 120 seconds, observation no older than 180 seconds, current duty and next unarrived visit). The assistant can answer by Order or driver and includes the provider observation time. Displayed traffic delay is cumulative added travel time, not lateness against an appointment. Neither Monitor reads nor assistant questions call the provider.

Order Watch must already be running to refresh ETA evidence; adding a key alone does not start a worker or create GPS. It can generate regular API usage. Monitor Google traffic colouring remains Google’s existing layer; the TomTom route ETA is a separate source. The existing road-path endpoint supplies only the authorized Order’s own stops, ordered by its assigned route; it does not reveal other customers’ stops or draw the entire shared route. Its metadata includes provider, applied truck profile and attribution. Unassigned Orders retain a Google road preview through their own stops, labelled “Road preview · no vehicle assigned” on Monitor. This display-only preview is not truck feasibility, dispatch, pricing or live ETA evidence. After assignment, the endpoint uses the assigned vehicle’s TomTom truck profile; missing profiles, dangerous goods and provider failures still fail closed without falling back to a car route. Monitor shows an unavailable-route notice when a path request fails.

## Access and costs

Confirm current TomTom account permissions, quotas, attribution, display and retention terms for the intended commercial fleet use before deployment. Free evaluation/API allowances are not a promise of unlimited free fleet tracking. Routing and Matrix Routing v2 have separate allowances; monitor both. This integration does not add turn-by-turn navigation licensing. Google services retain their own costs and terms.
