## Boundaries

Inbound email intake and AUTO dispatch are implemented as separate workers; running the API alone does not run either agent. Automatic booking requires a connected mailbox, configured extraction/geocoding providers, a verified active Shipper and complete booking facts; automatic assignment also requires AUTO mode and an eligible on-duty driver. Late-delivery replanning, payment collection, payroll and remote push delivery are not implemented. Android foreground location and a bounded encrypted driver action/evidence queue are implemented in the separate driver app; see its state file for verification limits. Road provider responses are not persistently cached. Evidence images are stored in PostgreSQL pending object-storage and retention work. Completion retains the booked price and never issues an invoice. Quote and delivery-update sending requires the separate SMTP worker. Partial quantity or failed delivery remains an issue requiring dispatcher resolution; full recovery/rebooking is not implemented.

The original client layouts are retained and now use these operational endpoints in company workspaces and role portals. `/prototype` is the separate local simulation. Browser demo records are not imported into PostgreSQL automatically.
